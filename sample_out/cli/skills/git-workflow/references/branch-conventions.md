# Branch Naming

## Format

`<type>/<short-name>` or `<short-name>`

Both are fine. Pick one and stay consistent in the repo.

## Examples

- `feature/social-login`
- `fix/parser-crash-on-empty`
- `refactor/extract-user-model`
- `docs/api-readme-update`

## Rules

- Lowercase, kebab-case
- No spaces or underscores
- Short — 3-5 words tops
- Describe the task, not the agent doing it

## Avoid

- `woodstock-feature-x` — branches don't belong to agents
- `branch-1` — meaningless
- `fix` — too vague
- `feature/SocialLogin` — wrong case
