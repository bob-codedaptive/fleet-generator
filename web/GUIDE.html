Fleet Generator

Set up a Claude agent team for your project in 5 minutes — or in 30 seconds.

1 Run the Generator and Pick a Path

Open fleet-generator.html in any browser — Chrome, Safari, Firefox. No install, no server. The first screen asks you to choose your path.

Path 1 — Guided install (~5 minutes)

Walk through 7 steps: project, repos, vocabulary, team, preferences, preview, download. Pick which agents you want, name them, write personas, choose your slash-command vocabulary, opt into the optional skills and hooks you want.

Best when: you want to customize from scratch and learn the pieces as you go. Output is a tailored fleet for one project.

Path 2 — One-shot install with sample settings (~30 seconds)

Type a repo path. Click. Done. We pick sensible defaults: every agent, every optional skill, every hook, the maintenance doctrine, and a starter audit mission. Drops a complete self-maintaining fleet into your repo.

Best first run: a fresh, empty repo. Get familiar with the agents and how they work without affecting real code.

Safe in production repos too — the installer never overwrites your existing CLAUDE.md or settings.json (saved alongside as *.fleet). But for a real product repo, Path 1 is preferred so you choose names, vocabulary, and only the agents/hooks you actually want.

Path 3 — Install fleet-generator as a project (~30 seconds, for power users)

Workshop mode. Bundles a copy of fleet-generator.html into a workspace and ships agents that know how to edit it. Add features and customize defaults over time — every future project you generate from your fork inherits your additions. Includes a 3-mission tutorial ladder that teaches the file by editing it.

Best when: you'll be using this generator across many projects and want to evolve it to match your team's specific patterns. Output is a personal workshop.

Paths 2 and 3 download immediately. Path 1 walks you through the wizard and downloads at the end. All three produce a single zip you unzip and install.

3 Install the CLI Side

Unzip the download. Open Terminal in the unzipped folder. Run:

bash install.sh /path/to/your/repo

The installer creates .claude/ directories and copies in agents, skills, rules, hooks, and missions. If your repo already has a CLAUDE.md or settings.json, the new versions land alongside as *.fleet so you can review and merge — nothing gets overwritten.

Run install.sh against multiple repos by re-running it with each repo path. Each repo gets the same agent system installed.

4 Install the Chat Side

Open chat/ in Finder (or your file manager). You'll see one .zip per chat skill.

  1. Open claude.ai (or Claude Desktop)
  2. Click your name (bottom-left) → Settings → Capabilities → Skills
  3. Drag the .zip files in. Multi-select works — drop them all at once for bulk install.
  4. Open a chat. Type your scope command (e.g. /scope or whatever word you chose) to enter investigation mode.

5 Updating Chat Skills After You Install Them

The constraint: Claude App (claude.ai web and Claude Desktop) loads skills into a chat session when the chat is initiated. Once that chat is running, you can't update its skills. New versions you upload won't take effect in chats that were already open when you uploaded.

This matters because fleets evolve. You'll fix a skill, want it live, and find the old version still running in your active chat. Here's the workaround.

To get a skill update into a running chat

  1. Upload the new .zip in Settings → Capabilities → Skills (replaces the old one).
  2. Quit the Claude app entirely. Restart it.
  3. In your OLD chat (the one with the stale skills), run your continuity command. The skill writes a HANDOFF PACKET artifact summarizing the chat state.
  4. Start a NEW chat. Paste the HANDOFF PACKET. The new chat picks up your fresh skills automatically.
The continuity skill exists specifically to make this transition cheap. It packages the active mission, decisions, and pending work into a compact paste-able artifact so you don't lose context across the chat boundary.

Claude Code has no such limitation

Claude Code reads .claude/skills/<name>/SKILL.md fresh from disk on every invocation. Edit the file, save it, and the next command picks up the new version. No restart needed. This is one of the major behavioral differences between the two surfaces and worth keeping in mind when you choose where to iterate on a skill.

Workflow tip: Iterate on skill content from the CLI side first. When the SKILL.md is settled, regenerate the fleet from the HTML to refresh the chat-side .zip, then upload it.

Vocabulary is customizable. If you called scoping "investigate" in the wizard, your command is /investigate instead of /scope. All chat skills, reference files, and the CLI CLAUDE.md use the words you picked.
Reserved slash commands. The wizard blocks vocabulary words that collide with Claude's built-in slash commands — /plan, /clear, /init, /memory, /model, /agents, /skills, /hooks, /mcp, /permissions, /settings, /help, /loop, /schedule, /security-review, /ultrareview, /statusline, and others. Typing them would trigger the built-in, not your skill. Pick a different word.

7 Self-Maintenance (Quick Start)

If you used Quick Start, your fleet ships preconfigured to keep improving over time. Two extra skills and one starter mission do the work:

The maintenance kit

  • agent-fleet-builder — the A-grade rubric across seven categories (subagents, skills, hooks, rules, memory, models, docs) plus the references/wave-methodology.md for disciplined, measurable iteration.
  • canonical-skill-source — governance. Pick one source location for fleet edits; deploy from there. Without this, fleet content scatters across repos and drifts apart.
  • MISSION_SELF_AUDIT.md — the starter mission. Walks the orchestrator through Wave 1: grade each category against the rubric, identify the lowest grade, propose Wave 2.
Run MISSION_SELF_AUDIT roughly monthly, or whenever the fleet feels off. The audit produces docs/fleet-audits/WAVE_N_REPORT.md — read it, decide which fix to ship next, then write a real mission for that fix.

Requires MOOTx01. Leave the box unchecked if you are not running it: the commands assume an estate to write to.

A checkbox, off by default. On, it adds three commands for the compact ritual:

CommandWhat it does
/prepare-for-compactWrites the handoff in the agent's own words and files it to the estate, then tells you to run /compact.

The handoff and plan-capture skills ship in the base bundle regardless. They are written against “your memory system”, so they work with any store; the checkbox adds what makes the ritual one keystroke instead of a paragraph typed by hand.

Two agents working from one directory. /recover-from-compact filters candidate handoffs on repository, then agent, then recency, and stops and asks when more than one survives. A wrong handoff does not announce itself: it reads as perfectly coherent context for work nobody was doing.

10  Model Tiers

The generated fleet no longer puts every agent on one model. Three roles, three choices, made together:

RoleModelWhy
Reviewertop tierOne pass over a finished diff. Cheap, and the only thing between a plausible-looking change and your main branch.
Orchestratortop tierPays for itself if it dispatches. If it types the code itself it is the most expensive possible arrangement.
Workersmid tierThey receive a brief containing everything they need, so capability buys less here than anywhere else.

A model class implies an agent-file shape. Keep two variants of the orchestrator: the full procedural file for the smaller model, and a lean one for the capable model. Measured on one identical task across eight configurations, the lean file halved the cost of the capable model and passed, while making every smaller model more expensive and no better.

Running a capable model against the full file is the most common setup error. It reads as the safe choice and is not: the model spends context on scaffolding it does not need, has less left for the work, and starts doing the work itself rather than dispatching.

Edit MODEL_TIERS near the top of the wizard's script block to change the defaults.
